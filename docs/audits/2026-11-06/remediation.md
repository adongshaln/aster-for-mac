# Aster 4.4.0 整改与验收

本轮根据 [原审查](review.md) 进行整改。普通任务改为运行官方 DeepSeek Harness SDK 与运行时，不再由同名工具和自写短循环模拟 dsh。提示词注入预设、过滤与序列化保持原样。

## 执行架构

固定 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-sdk-client` 为 `0.2.2-rc.1`，参考源码提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`。MIT 与 Node.js 许可随 App 分发。

Electron 45 的 V8 指纹不能直接加载此版本 dsh 的原生依赖，因此打包独立 Node 24.11.1。Electron 主进程保管真实服务密钥，由每次请求独立的回环代理转发模型调用；SDK 子进程只持有临时代理令牌。代理保留自定义地址、接口路径、请求头与推理配置。Aster 插件仅承担流式事件、权限策略、网页工具与产物的界面桥接。

每轮关闭运行时后保存完整 dsh 历史。下一轮从完整检查点恢复；重新生成另起分支，原分支保留。切换工作区会同步调用原生工作目录接口。删除会话会先结束该会话的任务，再删除相应 dsh 历史。原对话首次迁移只可导入已有正文，不能补回旧版未保存的工具结果。

## 验收方式

使用本地 HTTP 模型替身、临时工作区和临时用户数据目录；原生集成测试确实启动所分发 SDK、Node、工具与持久化模块。`tests/desktop-smoke.cjs` 和 `tests/desktop-design.cjs` 则直接启动打包后的 Aster.app。

最终 **37 项回归通过、0 失败**，类型检查和打包通过；桌面多问题续轮、产物边界、Mermaid、Tab 焦点和 Esc 检查通过。结果与截图见本目录 `after/`。不使用真实密钥、不读取用户个人对话。测试验证执行机制及界面行为，不代表已经测得真实模型任务成功率或完整 dsh 产品等价性。

## 保留的边界

- 按要求，启用提示词注入时继续使用原兼容路径；注入模块未迁入 dsh，旧路径的短工具循环限制仍适用。关闭任务工具时为直接对话路径。
- 当前请求结束时会关闭其 dsh 进程，未完成后台作业随之清理。任务内长命令可通过 job_output 等待；跨请求常驻开发服务器尚未提供。
- 压缩遵守 dsh 的近期原文保留和完整工具调用配对规则，不能保证任意单条超长消息都能压缩。
- 本轮没有使用付费真实模型执行综合任务基准；也没有增加代码签名、公证或自动更新。
